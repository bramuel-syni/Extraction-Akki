# **§12 — Northena's mandate**
**The UI specification cuts the buyer flow from the platform and rehomes it to a separate commercial product. **The product system document and the Role Register both describe a buyer journey. The reconciliation: the buyer is an end-user of a commercial application, that application holds a scoped external key, and it passes the same governed boundary as any third party. The buyer journey exists; it does not exist on a platform console. The Surfaces document states this; the Marketing Briefing describes the buyer experience without implying a platform surface.
**The consequence for the published set. **The Surfaces document carries it as §15A rather than as an audio-specific screen, and the objective-tracking surface it adjusts is the one already specified for extraction commissions. A reader should not conclude that audio work has a separate surface, because building one would be the parallel-machinery defect the plane’s own doctrine forbids.
Every constitutional document, every requirements specification, every surface document, and the Role Register. The complete list is Parts I §§1–3.

# **§16 — What would close the outstanding set**
**Reading the Function-Promise Registry and reconciling its rows against the Quality Rule Book's schema section. **This is the one gap with product consequence: if the registry as populated diverges from the schema as specified, the Quality Rule Book describes a discipline the build does not run. Everything else outstanding is build-process canon whose absence does not affect what the published set says about the product.

*Why this register is short on comfort. A documentation set that claims complete coverage of its sources without showing the working is asking to be believed, which is the one thing this platform is built not to require. What is read is listed; what is not read is listed with its consequence; and where a published claim outran its evidence, the claim is corrected here rather than quietly amended. The corrections do not weaken the architecture — every one of them describes a guarantee the design holds and the build has not yet fully enforced.*
