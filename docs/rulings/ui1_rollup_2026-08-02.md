## B · Journeys walkable

End-to-end journeys the Owner can walk from `/` in the preview:

1. **Connect → Registry → Use Data (canonical operator flow):**
   `/` → `/connect` (see connected sources + rules) → `/registry` (see what the estate holds by ring/source/domain, measured vs unmeasured) → click a `Put this to work` CTA on an opportunity brief → `/use-data?prefill_from_brief={id}` opens a prefilled Use Data conversation.

2. **Prove ↔ Registry (gap → queue → session):**
   `/prove` (default renders 4 shape grammar reference cards) → submit a novel question → NOT_EXTRACTED_YET renders with `Queue this gap` button → click → creates gap → `/registry` gap-register shows it as `open` → click `Queue this gap` on the row → opens Use Data session prefilled from the gap.

3. **Walk-a-Proof descent + close (Canon §9.2):**
   `/prove` → submit ANSWERED question → click `Walk this proof` link → `/prove/trace/{trace_id}` renders 3 layers (claim → reasoning → raw facts with source links) → click Close → returns to `/prove` at same scroll position (React Router location.state).

4. **Govern rule-change ceremony (Canon §7.5):**
   `/govern/change-rule` (DPO) → initiate rule change with 2-checker discipline → checker request appears in `/govern/holds` and in `/team/approval-surface` (same underlying record · link-across) → master_admin approves via Team surface with verbatim reason → decision mirrored to `checker_requests.team_decisions` → visible on Govern rule-changes bucket.

5. **Team approval → Govern record (Owner Message 610 D-1):**
   `/team/approval-surface` → approve any chk-* item with reason → confirmation shows `Open the Govern record →` link → `/govern/holds?session_id=X` renders SAME underlying record with the decision event.

6. **Team grant → Engineer surface (Owner Message 610 grant→login→propagation):**
   `/team/access-register` (master_admin) → issue grant → grant_id returned → GET `/api/engineer/key_grants?grantee_email=X` returns SAME grant_id → revoke via Team → engineer surface shows revoked_at + revocation_reason. **Single-source engineer_key_grants machinery verified end-to-end.**

7. **DPO break-in (Owner Message 610 D-2):**
   Sign in as DPO → `/team/access-register` (grant form replaced by role-denial banner · rows visible · no revoke buttons) → attempt POST /grant → 403 auth_scope_insufficient in correct shape.

8. **Trust Center honesty walk (Canon §7.1):**
   `/govern/trust-center` renders 5 machinery+attestation blocks with plain-language honest counts (3 enforced · 1 attested · 1 monitored) · absorbed/rejected refusal reasons visible verbatim.

9. **Constitutional record (Canon operating model A.5):**
   `/team/constitutional-seats` renders Master Admin + DPO seats with holder emails · succession action DORMANT-HONEST (button disabled · reason mentions HAZARD-STOP · succession path narrative describes counter-signature requirement).
